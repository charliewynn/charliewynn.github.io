Solving "twisty puzzles" is a trade off between the number of turns and the number of algorithms needed. This is true for both figuring out a new cube for the first time and for creating a reproducible set of steps to follow.

Some people memorize over a hundred algorithms for a 3x3x3 (standard Rubik's cube). You could argue that if you exclude "intuitive" algorithms you only need 3-4 "real" algorithms to solve one. The 3-4 algorithm method won't win you any prizes but for me it's more fun to figure out the minimum amount of steps.

# My method for a new cube

With a new cube I usually try to fumble around until I get to one layer with just a few unsolved pieces. I rinse and repeat until I can get to a common roadblock. Sometimes you can get lucky and get to a solve from there. From there I'll note all of the pieces and try an algorithm from a similar cube to see if that helps move the remaining pieces around. If that doesn't work I'll try random new algorithms that "feel" like they might swap the remaining pieces around in a predictable way.

The remaining algorithm(s) will usually only work in a few situations. But using [Commutators](https://youtu.be/7LTCEyrQk44) or [Conjugates](https://youtu.be/3WLb0VddFNg) you can usually transform the algorithm into something useful for your situation.
